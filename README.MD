## Описание

EventManager позволяет зарегистрированным пользователям создавать мероприятия, управлять записью участников и публиковать фотоотчёты. Все мероприятия проходят обязательную модерацию перед публикацией. Незарегистрированные посетители могут просматривать опубликованные мероприятия без авторизации.

## Архитектура приложения

Приложение построено по классической многоуровневой архитектуре:

    ┌────────────────────────────────────────────────────────┐ 
    
    │ Thymeleaf Templates │ ← Server-side rendering          │
    
    ├────────────────────────────────────────────────────────┤ 
    
    │ MVC │ REST API (/api/**) │ ← Страницы + Ajax-эндпоинты │
    
    ├────────────────────────────────────────────────────────┤ 
    
    │ Service Layer    │ ← Бизнес-логика + ACL               │
    
    ├────────────────────────────────────────────────────────┤ 
    
    │ Repository Layer │ ← Spring Data JPA                   │
    
    ├────────────────────────────────────────────────────────┤ 
    
    │ PostgreSQL       │ ← База данных                       │
    
    └────────────────────────────────────────────────────────┘


Страницы отдаются через Thymeleaf (SSR). Динамические действия без перезагрузки страницы (запись на мероприятие, комментарии, галерея, модерация) реализованы через `fetch()` к REST-эндпоинтам.

## Роли пользователей

| Роль      | Описание                                                                 |
|-----------|--------------------------------------------------------------------------|
| `USER`    | Роль по умолчанию. Создаёт мероприятия, записывается, комментирует       |
| `MANAGER` | Модерирует мероприятия: одобряет или отклоняет перед публикацией         |
| `ADMIN`   | Управляет пользователями: назначает роли, блокирует аккаунты             |

При первом запуске автоматически создаётся пользователь **admin** с ролью `ADMIN`.

## Функциональность

### Для незарегистрированных пользователей
- Просмотр главной страницы со списком опубликованных мероприятий (пагинация по 10)
- Просмотр страницы конкретного мероприятия с описанием и комментариями
- Регистрация по логину и паролю

### Для пользователей (USER)
- Создание мероприятий с указанием: названия, описания, обложки, даты, стоимости и количества мест (0 — без ограничений)
- Редактирование собственных мероприятий в статусах `PENDING` и `REJECTED`
- Установка статуса «Мероприятие состоялось» для опубликованных мероприятий
- Добавление фотографий в галерею завершённых мероприятий
- Запись и отмена записи на чужие мероприятия
- Управление участниками своего мероприятия: отклонение, отметка об оплате
- Комментирование мероприятий (с указанием роли: организатор / участник)
- Личный кабинет: список организованных мероприятий, список записей, смена пароля

### Для менеджеров (MANAGER)
- Список мероприятий на рассмотрении
- Одобрение или отклонение мероприятий
- Удаление любых комментариев и фотографий

### Для администраторов (ADMIN)
- Список всех пользователей с возможностью назначения ролей
- Блокировка и разблокировка аккаунтов

### Жизненный цикл мероприятия
    PENDING → APPROVED → COMPLETED 
        
            ↘ REJECTED


| Статус      | Отображается на главной | Доступна запись | Доступна галерея |
|-------------|------------------------|-----------------|------------------|
| `PENDING`   | ❌                      | ❌               | ❌                |
| `APPROVED`  | ✅                      | ✅               | ❌                |
| `REJECTED`  | ❌                      | ❌               | ❌                |
| `COMPLETED` | ✅                      | ❌               | ✅                |

## Быстрый старт с Docker

Самый простой способ запустить приложение целиком:
# 1. Сборка JAR
    ./gradlew bootJar
# 2. Запуск приложения и базы данных
    docker compose up --build


Приложение будет доступно по адресу: **http://localhost:8080**

Учётные данные администратора по умолчанию:
- Логин: `admin`
- Пароль: `admin`

> ⚠️ Смените пароль администратора после первого входа в личном кабинете.

### Остановка
    docker compose down

Удалить также тома с данными БД и загруженными файлами

    docker compose down -v

## Локальный запуск для разработки

### 1. Запустить только базу данных в Docker
    ./gradlew bootRun


Или запустите `EventManagerApplication` напрямую из IDE.

Приложение подключится к базе данных на `localhost:5462` (порт задан в `application.yaml`).

> **Примечание для Windows:** если порт `5462` недоступен из-за резервирования системой,
> проверьте занятые диапазоны командой:
> ```powershell
> netsh interface ipv4 show excludedportrange protocol=tcp
> ```
> И при необходимости измените маппинг порта в `docker-compose.yml`.

### 3. Хранение загружаемых файлов

При локальном запуске файлы сохраняются в папку `uploads/` в корне проекта.
Папка создаётся автоматически при первой загрузке файла.

## Переменные окружения

Все переменные имеют значения по умолчанию, подходящие для локальной разработки.

| Переменная               | По умолчанию          | Описание                              |
|--------------------------|-----------------------|---------------------------------------|
| `DB_HOST`                | `localhost`           | Хост базы данных                      |
| `DB_PORT`                | `5432`                | Порт базы данных                      |
| `DB_NAME`                | `eventmanager`        | Имя базы данных                       |
| `DB_USER`                | `eventmanager`        | Пользователь базы данных              |
| `DB_PASSWORD`            | `eventmanager`        | Пароль базы данных                    |
| `UPLOAD_PATH`            | `uploads`             | Путь для хранения загруженных файлов  |
| `ADMIN_DEFAULT_PASSWORD` | `admin`               | Пароль администратора при первом запуске |

В Docker Compose переменные задаются в секции `environment` сервиса `app`.

## Запуск тестов

Для запуска тестов требуется **запущенный Docker Desktop** — тесты используют Testcontainers для поднятия реального PostgreSQL-контейнера.

Запустить все тесты
    
    ./gradlew test

Запустить тесты конкретного класса

    ./gradlew test --tests "ru.musintimur.eventmanager.service.EventServiceTest"

Запустить с подробным выводом

    ./gradlew test --info

Отчёт о результатах тестов: `build/reports/tests/test/index.html`

### Состав тестов

| Пакет        | Класс                       | Что проверяется                              |
|--------------|-----------------------------|----------------------------------------------|
| `repository` | `UserRepositoryTest`        | Поиск и существование пользователей          |
| `repository` | `EventRepositoryTest`       | Фильтрация мероприятий по статусу и автору   |
| `service`    | `UserServiceTest`           | Регистрация, смена пароля, управление ролями |
| `service`    | `EventServiceTest`          | Создание и смена статусов мероприятий        |
| `service`    | `RegistrationServiceTest`   | Запись, отмена, управление участниками       |
| `controller` | `HomeControllerTest`        | Главная страница и пагинация                 |
| `controller` | `AuthControllerTest`        | Регистрация, вход, доступ к защищённым URL   |
| `controller` | `EventControllerTest`       | CRUD мероприятий, проверка прав доступа      |
